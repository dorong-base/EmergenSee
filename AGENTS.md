# Base44 development notes

- Use `docker compose -f docker-compose.base44.yml up -d --build`. The repository's original Compose file is infrastructure-only; the Base44 file runs editable source with Vite and Nest watch mode.
- The one-shot `dependencies` service installs the pinned pnpm workspace lockfile and builds `@emergensee/shared` before either app starts. Its CommonJS `dist` is required by Nest even though Vite imports shared TypeScript source. After shared-package edits, rebuild it with `docker compose -f docker-compose.base44.yml exec api corepack pnpm --filter @emergensee/shared build`.
- Only port 3000 is exposed. Vite forwards `/api` to the API, strips the prefix, and proxies WebSocket upgrades. `VITE_API_URL` must be an absolute URL because websocketService constructs it with `new URL(...)`; Compose derives it from `BASE44_PUBLIC_HOST_SUFFIX`.
- MongoDB is private to the Compose network and uses a persistent volume. No migrations or seeds are needed for the login screen. The database starts empty; users can self-register (MEMBER role, not administrator). Redis appears in the original Compose but no application code uses it.
- JWT_SECRET and JWT_REFRESH_SECRET are required. Generated development keys are delivered via `/run/base44/app.env`, never committed or placed in Compose environment overrides. Optional Google client IDs and face-recognition URLs are also supplied there; dashboard values take precedence.
- Google token sign-in needs GOOGLE_CLIENT_ID and matching VITE_GOOGLE_CLIENT_ID. The unused Google OAuth strategy is not registered, so GOOGLE_CLIENT_SECRET is not needed. Missing Google client IDs do not block email/password auth.
- Face-recognition server code is absent from this repository. Camera/face features require an external service configured with FACE_RECOGNITION_URL (backend) and VITE_FACE_API_URL (browser-accessible HTTPS URL with CORS). Do not claim those features work without that service. Existing face uploads persist in a separate Docker volume.
- Checks: `docker compose -f docker-compose.base44.yml ps` should show mongodb/api/web healthy. `curl -fsS http://localhost:3000/` must include `/@vite/client`; `/src/main.tsx` serves live compiled source. `/api/docs-json` checks the real API through the preview proxy; `/api/socket.io/?EIO=4&transport=polling` checks realtime routing. API healthchecks use existing `/docs-json`, not a new endpoint.
- Browser setup verification: `/login` renders without console errors, failed requests, or a Vite overlay. Optional integrations were skipped during setup. No demo accounts or application data were seeded.
